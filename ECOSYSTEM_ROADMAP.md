# Roadmap — publish-skill

Part of the [AI Video Production OS](https://github.com/kajisho5/AI-video-production-OS/blob/main/docs/ecosystem/ROADMAP.md) ecosystem: department **納品 (Delivery)**, status `active`.
Written from a read-only audit of this repository on 2026-10-30. Each step below is meant to be one pull request; tick it off by linking the PR.

## Where it stands

0.2.0 (released from v0.1.0 on; step 11). Scaffold ([#4](https://github.com/kajisho5/publish-skill/pull/4)): `contract`, `doctor`, `platforms` and the dry run of `upload` behind a per-deliverable confirmation token (ADR-001). `publish plan` ([#5](https://github.com/kajisho5/publish-skill/pull/5), ADR-002): the deliverable and its metadata against YouTube's cited upload limits and ffmpeg-skill's `check`, offline; the token binds the metadata. Credentials ([#6](https://github.com/kajisho5/publish-skill/pull/6), ADR-003): the environment or the OS keychain (`publish auth login|status|logout`, keyring as an optional extra), never printed. YouTube uploader ([#7](https://github.com/kajisho5/publish-skill/pull/7), ADR-004): the Data API v3 resumable upload of the video, thumbnail and captions after the exact confirmation token, tested against a loopback mock only; no real upload has been made yet. Vimeo uploader ([#8](https://github.com/kajisho5/publish-skill/pull/8), ADR-005): the tus resumable upload of the video with its title, description and privacy (`nobody` by default) after the exact confirmation token, with a personal access token, tested against a loopback mock only. TikTok uploader ([#9](https://github.com/kajisho5/publish-skill/pull/9), ADR-006): the Content Posting API Direct Post (creator info, init with FILE_UPLOAD, chunked PUT, the post's status) with its title and privacy (`SELF_ONLY` by default) after the exact confirmation token, with a user access token, tested against a loopback mock only. X uploader ([#10](https://github.com/kajisho5/publish-skill/pull/10), ADR-007): the X API v2 chunked media upload and one public post with the title as its text, after the exact confirmation token, with an OAuth 2.0 user access token, tested against a loopback mock only. LinkedIn uploader ([#11](https://github.com/kajisho5/publish-skill/pull/11), ADR-008): the Videos API multipart upload and one public post with the title as its escaped commentary, after the exact confirmation token, with a member access token and the author's URN, tested against a loopback mock only. Facebook uploader ([#12](https://github.com/kajisho5/publish-skill/pull/12), ADR-009): the Resumable Upload API and one Page video with its title, description and privacy (public or unlisted), after the exact confirmation token, with a user and a Page access token, tested against a loopback mock only. Instagram Reels uploader ([#13](https://github.com/kajisho5/publish-skill/pull/13), ADR-010): a resumable REELS container, the rupload upload and one public reel with the title as its caption, after the exact confirmation token, with a Facebook Login for Business token, tested against a loopback mock only. Step 5 is complete. Chapters, a scheduled time and localized metadata ([#17](https://github.com/kajisho5/publish-skill/pull/17), ADR-011): `plan` checks YouTube's chapter rules; YouTube uploads carry `status.publishAt`, a default language, localizations and one caption track per language. Clips as a series ([#18](https://github.com/kajisho5/publish-skill/pull/18), ADR-012): `publish series` uploads a manifest of clips in order, each with its own token and a link back, resuming after a failure without sending any clip twice. Restricted delivery ([#19](https://github.com/kajisho5/publish-skill/pull/19), ADR-013): Vimeo password and domain-limited privacy, and an organiser's delivery receipt per session (URL, privacy, sha256). The limits verdict (ADR-015): this skill's cited duration and file-size limits decide `plan`'s verdict; ffmpeg-skill's duration and size rows are shown as guidance.

## Wiring

The agent plans `publish.upload` as a CONFIRM decision after QC, runs only `plan` and the `upload` dry run, and uploads once on `video-agent publish --confirm` (step 6, video-production-agent#99). No real upload has been made yet.

## Boundaries

Platform delivery specs (配信プラットフォーム仕様) are owned by ffmpeg-skill (owner decision, 2026-10-30); this skill reads them and owns only upload-side limits (アップロード制限). For duration and file size, this skill's values are authoritative and ffmpeg-skill's rows are guidance ([Velisa ownership decisions 2026-11-12](https://github.com/kajisho5/Velisa/blob/main/docs/ecosystem/DECISION_LOG.md)).

Gap: the Vimeo delivery spec has no owner. ffmpeg-skill has no `vimeo` spec and this skill does not write one (`limits.py:47`), so `plan` reports it UNCHECKED until an owner is decided in Velisa.
